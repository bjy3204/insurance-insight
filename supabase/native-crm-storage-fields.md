# 연결 없이 사용하기 저장 항목 확인

확인 기준: 2026-10-18 현재 model.ts, native-records.ts, native API.

고객·계약·차량·일정 모두 customer_records의 payload_version=2로 저장합니다. 각 레코드의 source와 values 전체는 서버에서 AES-256-GCM으로 암호화됩니다. 개인정보별 SQL 열 추가는 필요하지 않습니다.

## 공통 메타데이터 및 제한

- id, user_id, encrypted_payload, encryption_key_id, payload_version, revision, created_at, updated_at
- 등록일·수정일은 created_at·updated_at으로 유지합니다.
- 체크리스트의 일정, 알릴의무의 병력, 상담일지의 상세 기록은 각 상세 JSON 안에 저장합니다.
- 생일·상령일·D-day와 면책·감액 만료일은 저장된 생년월일·계약일·기간에서 계산합니다.
- 카드수납은 저장하지 않습니다. 엑셀 주민번호는 앞 7자리로 잘라 등록하며 API는 전체 13자리를 거부합니다.
- 기존 외부 노션·스프레드시트 자료를 자동 병합하지 않습니다.
- SQL은 기존 테이블이 없으면 생성하며, 이미 있으면 소유자·버전 조회용 인덱스와 서버 전용 권한을 적용합니다.
- 기존 CUSTOMER_DATA_ENCRYPTION_KEY를 변경하면 기존 자료를 복호화할 수 없습니다.
- 실제 Supabase 실행은 수행하지 않았습니다. 검증 테스트는 모의 DB를 사용합니다.
